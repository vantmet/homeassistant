# Home Assistant Configuration

This repository contains the version-controlled configuration for Home Assistant, managed and synchronized via the [Git HA-ppens](https://github.com/manuveli/git-ha-ppens) custom integration.

* **Upstream Remote:** `git@github.com:vantmet/homeassistant.git` (or `https://github.com/vantmet/homeassistant.git`)
* **Sync Engine:** [Git HA-ppens](https://github.com/manuveli/git-ha-ppens) (Native GitOps file watcher & sync integration)

---

## Repository Structure

| File / Folder | Description |
|---|---|
| [`configuration.yaml`](configuration.yaml) | Base configuration file loading themes, default configs, `predbat_requested_mode` helper, and charge/discharge rates. |
| [`automations.yaml`](automations.yaml) | All automations, including Solcast forecast updates, Predbat EMS control mappings, and smart lighting. |
| [`scripts.yaml`](scripts.yaml) | Reusable scripts (e.g., Hive heating boost). |
| [`scenes.yaml`](scenes.yaml) | Configured Home Assistant scenes. |
| [`blueprints/`](blueprints/) | Automation and script blueprints (motion lighting, zone departure, confirmable notifications). |
| [`solcast_solar/`](solcast_solar/) | Solar forecast cache, actuals, site configs, and usage data generated by the Solcast Solar integration. |
| [`www/community/`](www/community/) | Custom Lovelace frontend cards installed via HACS (Bubble Card, Predbat Card, ApexCharts Card, Pi-hole Card). |
| [`.gitignore`](.gitignore) | Auto-generated and maintained by Git HA-ppens to protect secrets and ignore transient runtime files. |

---

## What Is NOT Tracked (Important)

In accordance with [Git HA-ppens](https://github.com/manuveli/git-ha-ppens) best practices and security standards, the following files are excluded via [`.gitignore`](.gitignore) and are **not** stored in this repository:

1. **`secrets.yaml`**: Contains private passwords, tokens, API keys, and device credentials.
2. **`.storage/`**: Internal Home Assistant database containing UI-configured integrations, user accounts, authentication tokens, and entity registries.
3. **`custom_components/`**: Python code for custom integrations installed via HACS (e.g., `git_ha_ppens`, `solcast_solar`, `predbat`).
4. **Database & Logs**: `home-assistant_v2.db`, `*.log`, SQLite journals/WAL files.
5. **Backups**: `backups/*.tar`.

> [!WARNING]
> Because `secrets.yaml` and `.storage/` are gitignored, cloning this repository alone does not restore private credentials or UI-added integration entries. Always retain a secure copy of `secrets.yaml` and regular full Home Assistant backups.

## Deploying a New Home Assistant Instance

When provisioning a new Home Assistant instance (e.g., new hardware, disaster recovery, or clean rebuild), follow one of the two deployment methods below.

### Method 1: Clean Install + Git HA-ppens (Recommended UI / GitOps Method)

This method uses the official [Git HA-ppens](https://github.com/manuveli/git-ha-ppens) integration to bootstrap and manage the configuration.

#### Step 1: Install Home Assistant & Complete Onboarding
1. Install Home Assistant (OS, Container, or Supervised) on your target system.
2. Complete the initial onboarding wizard to create your owner user profile.

#### Step 2: Install HACS (Home Assistant Community Store)
1. Install HACS following the [official instructions](https://hacs.xyz/docs/use/).
2. Restart Home Assistant and complete HACS GitHub authorization.

#### Step 3: Install the Git HA-ppens Integration
1. In Home Assistant, open **HACS** > **Integrations**.
2. Click the three dots (`⋮`) in the top right corner and select **Custom repositories**.
3. Add:
   * **Repository**: `https://github.com/manuveli/git-ha-ppens`
   * **Type**: `Integration`
4. Click **Add**, locate **Git HA-ppens** in the list, and click **Download**.
5. Restart Home Assistant (**Developer Tools** > **YAML** > **Restart**).

#### Step 4: Configure GitHub Authentication
Ensure your Home Assistant instance can authenticate with GitHub:
* **Option A: SSH Key (Recommended)**:
  1. Generate an SSH key pair inside your Home Assistant instance (e.g. via Terminal / SSH add-on):
     ```bash
     ssh-keygen -t ed25519 -C "homeassistant-githappens" -f /config/.ssh/id_ed25519 -N ""
     ```
  2. Add the public key (`/config/.ssh/id_ed25519.pub`) as a **Deploy Key** with **Write Access** (or add to your GitHub account keys) at `https://github.com/vantmet/homeassistant/settings/keys`.
* **Option B: Personal Access Token (HTTPS)**:
  1. Generate a GitHub Personal Access Token (classic or fine-grained) with `repo` read/write permissions.

#### Step 5: Set Up Git HA-ppens Integration
1. Navigate to **Settings** > **Devices & Services** > **Add Integration**.
2. Search for and select **Git HA-ppens**.
3. Follow the 3-step configuration flow:
   * **Step 1 (Repository Details)**:
     * Set repository path to `/config`.
     * Enter your Git Author Name and Email.
   * **Step 2 (Auto-Commit & Auto-Push)**:
     * Configure debounce interval (e.g., 300 seconds / 5 minutes).
     * Enable auto-commit and auto-push according to your preference.
   * **Step 3 (Remote & Synchronization)**:
     * **Remote URL**: `git@github.com:vantmet/homeassistant.git` (or HTTPS URL).
     * **Auth Method**: `ssh` (specifying `/config/.ssh/id_ed25519`) or `token` (specifying your PAT).
     * Enable **Auto-Pull** and set fetch interval (e.g., 300 seconds).

#### Step 6: Pull & Synchronize
1. Trigger a fetch and pull via **Developer Tools** > **Actions** (or Services):
   * Action: `git_ha_ppens.pull`
2. Git HA-ppens will pull down all tracked configuration files, automations, scripts, blueprints, and `www/` resources from `origin/main`.

#### Step 7: Restore Secrets & Missing Integrations
1. **Restore `secrets.yaml`**: Copy your backed-up `secrets.yaml` into `/config/secrets.yaml`.
2. **Reinstall Custom Components**: Install required HACS integrations used by the configuration:
   * `solcast_solar` (Solcast Solar)
   * `predbat` (Predbat)
   * Any additional integrations referenced in your automations.
3. If using Lovelace UI dashboards that reference cards in [`www/community/`](www/community/), ensure the dashboard resources are registered under **Settings** > **Dashboards** > **Resources**.

#### Step 8: Validate & Restart
1. Go to **Developer Tools** > **YAML**.
2. Click **Check Configuration**.
3. Once valid, click **Restart** to load the complete setup.

### Method 2: Direct Git Clone Bootstrap (CLI / Docker / Pre-Boot)

If setting up via command line or provisioning a Docker volume before starting Home Assistant:

1. **Clone the repository directly into the Home Assistant configuration directory**:
   ```bash
   # Clone directly into /config (or your mapped docker host volume)
   git clone git@github.com:vantmet/homeassistant.git /config
   cd /config
   ```

2. **Restore Secrets**:
   Copy your private `secrets.yaml` into place:
   ```bash
   cp /path/to/backup/secrets.yaml /config/secrets.yaml
   ```

3. **Launch Home Assistant**:
   Start your Home Assistant container or OS. Home Assistant will start up directly using the cloned `configuration.yaml`, automations, and scripts.

4. **Install HACS & Custom Components**:
   * Install HACS.
   * Install the custom integrations (`git_ha_ppens`, `solcast_solar`, `predbat`).

5. **Connect Git HA-ppens**:
   * In **Settings** > **Devices & Services** > **Add Integration**, add **Git HA-ppens**.
   * It will detect the existing repository at `/config` and resume file watching, auto-commit, and upstream synchronization.

## GitOps Workflow & Daily Usage

### Bi-Directional Synchronization
* **HA UI -> Git**: Any automation, script, or configuration changes made directly in the Home Assistant UI are detected by Git HA-ppens, debounced, committed, and pushed upstream to GitHub.
* **Git -> HA UI**: Changes committed and pushed to `main` (e.g., from VS Code or GitHub Pull Requests) are automatically fetched and pulled by Git HA-ppens on its scheduled fetch interval.

### Exposed Services & Actions
Git HA-ppens exposes actions you can trigger manually or inside automations:
* `git_ha_ppens.commit`: Force an immediate commit of staged/changed files.
* `git_ha_ppens.push`: Push local commits upstream.
* `git_ha_ppens.pull`: Pull upstream commits and update local configuration.
* `git_ha_ppens.sync`: Execute fetch, pull, commit, and push in sequence.

### UI Rollbacks
If a bad configuration is deployed, you can roll back directly from the UI:
1. Go to **Settings** > **Devices & Services** > **Git HA-ppens**.
2. Select **Configure** > **Restore configuration**.
3. Choose one of the recent commits (or enter a SHA) to cleanly roll back changes.
